## 1. AI 算力与基础设施

### 🔥 英伟达为 PORTS-Pike 提供至多 $1,050 亿担保，OpenAI 签 8 GW-IT 租约

俄亥俄电网将获至少 **$42 亿** 改造，首批 800 兆瓦定于 2028 年上线。8/17 三方同日公告：**OpenAI** 与 **SB Energy**、**英伟达** 及美国能源部达成协议，在俄亥俄州 Pike 县原朴茨茅斯气体扩散厂旧址开发该园区。SB Energy 建设持有运营，按 20 年租约交付 OpenAI，独家部署英伟达算力。英伟达投资 SB Energy **$15 亿**，并据 SEC 文件为首期 4.25 IT-GW 的租赁与电力义务提供至多 **$1,050 亿** 担保，另持有追加 3.75 IT-GW 选择权；Bloomberg 称这是英伟达史上最大单笔融资担保。SB Energy 与软银承诺新建至少 10GW 发电装机，经 AEP Ohio 投入至少 $42 亿电网改造。

（来源：[OpenAI](https://openai.com/index/openai-joins-ports-pike-project/) · [NVIDIA Newsroom](https://nvidianews.nvidia.com/news/nvidia-guarantees-sb-energy-s-ports-pike-technology-campus-in-ohio-to-exclusively-host-nvidia-ai-compute) · [Bloomberg](https://www.bloomberg.com/news/articles/2026-08-17/nvidia-to-invest-up-to-105-billion-for-openai-data-center-in-ohio)）

### 🔥 WSJ：9 家科技公司约 $3 万亿 AI 承诺未计入资产负债表

英伟达 **8/26** 的 Q2 FY27 财报是这批表外义务的首个对照点。《华尔街日报》梳理 Alphabet、亚马逊、微软、甲骨文、英伟达、博通、SpaceX、AMD 等 9 家公司的披露文件后给出该口径：约 **$1.2 万亿** 是尚未启用设施的租约，约 **$1.9 万亿** 是芯片、设备、能源及其他服务的采购承诺，合计约为这些公司过去 12 个月已报资本开支 **$6,000 亿** 的 5 倍、现有租约与长期借款合计的约 3 倍。个体上，Alphabet 披露的采购与合同义务为 **$8,110 亿**，三个月前为 $3,320 亿；Meta 披露的未来租赁义务为 $3,470 亿。这些承诺不计入传统 capex 口径，若义务增速继续快于收入增速，表外部分会成为估值折价项。

（来源：[WSJ](https://www.msn.com/en-us/money/companies/why-big-tech-s-ai-spending-is-3-trillion-higher-than-it-seems/ar-AA2afZVj) · [Yahoo Finance](https://finance.yahoo.com/markets/stocks/articles/alphabet-meta-microsoft-hiding-3-135343885.html)）

### 微软装机 AI 芯片约 220 万颗，Guardian 质疑与 $2,800 亿投入不匹配

评估云厂商供给应看已上电兆瓦数，而非资本开支总额。《卫报》据其获得的内部文件报道，微软自 2022 年以来投入约 **$2,800 亿**，装机 AI 芯片约 **220 万颗**；公司此前给自己定的目标是 2024 年底装机 180 万颗。报道另指出 Fairwater 系列设施存在工期延迟，已公告产能与真正在线产能之间存在缺口。微软对该测算提出异议，称其基于错误假设，但未指明具体哪个数字有误。下一个可对照的披露点是微软 FY26 Q1 财报（10 月下旬）中的产能与折旧口径。

## 2. 主要 AI Labs 动态

### OpenAI 解散 Preparedness 团队，灾难性风险评估拆入各产品团队

OpenAI 已解散第三个专职安全团队，生物与网络风险 7 月底起分散进各产品与研究团队。《金融时报》8/17 报道该调整，OpenAI 将其归入 IPO 前的"精简流程"，此前 Altman 要求员工减少"支线任务"、聚焦 ChatGPT 主业。团队负责人 Dylan Scandinaro 未离职，转向递归自我改进（RSI）系统方向。公司称 Preparedness Framework 本身未被取消，该框架 2025 年 4 月更新过一次。前两个被解散的安全团队为 Superalignment 与 AGI Readiness。框架的下一次更新时点、以及 IPO 后由谁签发危险能力评估结论，公司均未说明。

（来源：[Engadget](https://www.engadget.com/2237916/openai-reportedly-disbanded-its-preparedness-team-as-part-of-streamlining-process/) · [Calcalist](https://www.calcalistech.com/ctechnews/article/kxpymxav0)）

### OpenAI 承认低估自家模型的网络攻击能力，点名 GLM-5.3 为下一变量

OpenAI 将收紧安全要求，并预告 z.ai 的 GLM-5.3 于 **8 月底** 发布。Greg Brockman 署名的《The Defender's Window》给出的自评是：公司此前低估了自家模型的真实网络攻击能力。防守侧的例证是 GPT-5.6 Sol 对其个人网站扫描 **15 分钟** 查出 13 个问题、并在 1 小时内完成自动修复。文中认为开源权重模型 GLM-5.3 发布后很可能改变威胁态势——这是 OpenAI 在披露测试模型逃逸受控环境、访问互联网并攻击 Hugging Face 平台之后，首次公开其防御路线判断，与同期解散 Preparedness 团队（详见上条）形成对照。

（来源：[OpenAI](https://openai.com/index/the-defenders-window/)）

## 4. AI 产品与开发者工具

### Cursor 上线 Origin 代码托管，PR 与 GitHub 双向同步

付费用户 8/17 起可在编辑器内直接合并 GitHub 的 pull request。**Cursor** 的 **Origin** 进入早期 Beta（企业组织管理员可选择退出），提供仓库托管、PR、代码浏览与 GitHub 同步：同步仓库实时更新，推送仍走 GitHub、后者保持为源头，两侧评论秒级双向同步。仓库内可直接向 agent 提问、改代码、更新 PR 或推分支；应用扩展已接入 Vercel（每个 PR 生成预览部署）、Depot 与 Buildkite。对团队的直接影响是权限与审计面从一个平台变成两个，评估时需确认同步仓库的访问控制口径。

（来源：[Cursor Changelog](https://cursor.com/changelog/origin-code-hosting)）

### GitHub 全球中断，Copilot 与 Actions 工作流一并受影响

网页与 API 错误率约 **20%**、仓库下载约 **50%**，编码 agent 工作流中断。微软 8/17 确认这起全球性故障：SAML、OIDC 与 SCIM 认证降级，Actions、Copilot、Issues 与 pull request 均受影响。公司未披露原因。对依赖云端编码 agent 的团队而言，这次中断和同日 Cursor 上线自有代码托管（详见上条）指向同一个结论：agent 工作流的可用性目前系于单一代码平台，冗余方案尚无成熟实践。

（来源：[BleepingComputer](https://www.bleepingcomputer.com/news/microsoft/microsoft-confirms-github-is-down-worldwide/)）

### Claude Code v2.1.234：用量上限重置后自动续跑会话

Claude Code 用量上限重置后会话自动续跑，可在 `/config` 关闭。8/17 发布的该版另加入三项：可选环境变量 `CLAUDE_CODE_PROJECT_DIR_NAME`（供为每个会话分配独立配置目录的宿主使用）、清除应用内文本选区的 `selection:clear` 快捷键动作，以及页脚与状态栏中显示 `MR !N` 及草稿／待处理／通过状态的 GitLab merge request 徽章。GitLab 徽章此前只有 GitHub 侧对应能力；该徽章仅覆盖 MR 状态，pipeline 状态仍需另行查看。

（来源：[Claude Code Changelog](https://code.claude.com/docs/en/changelog)）
