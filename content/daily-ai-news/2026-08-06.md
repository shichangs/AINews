### Rust 为 rust-lang/rust 立 LLM 规矩：可审阅、不可创作

**1,281** 个待审 PR（8/5 时点）逼出 Rust 新政：审阅者可径直关闭不合规 LLM PR。政策由五个团队投票通过、8/5 生效、仅约束 rust-lang/rust 单库，自我概括为"可以用 LLM 答疑、分析、提炼、检查、建议、审阅，但不能创作"。细则：公开文档、PR 描述与评论中的 LLM 文本须明确标注；LLM 生成代码强制披露、强制配测试，门槛高于人写代码；健全性关键（soundness-critical）改动除非作者本身是领域专家否则不得由 LLM 生成。项目级推广此前未获共识；与 Zig 的全面禁止、Linux 内核"AI 只是工具"相比，Rust 给出按用途切分的第三条路径。下一节点：Rust 领导委员会正讨论设立专责 LLM 政策的子团队。

（来源：[Inside Rust Blog](https://blog.rust-lang.org/inside-rust/2026/08/05/rust-langrust-is-adopting-an-llm-policy/) · [Socket](https://socket.dev/blog/rust-moves-to-restrict-llm-use-in-contributions)）

### Sandisk 与 SK hynix 发布首个 HBF 技术规范

首个 **HBF** 技术规范 8/5 经 OCP 发布：单器件最高 **512GB**、带宽三档至 3TB/s。HBF 即高带宽闪存，规范由 Sandisk 与 SK hynix 在 FMS 2026 上联合推动，采用 8/16 层 NAND 堆叠与 UCIe 互连，带宽档位覆盖 0.4–3.0TB/s，定位为 HBM 与 SSD 之间的 AI 推理内存层——长上下文与海量 KV cache 正把推理需求推出系统内存的容量边界。联盟成员已包括 **Google** 与 Tenstorrent。对 AI 基础设施侧的意义：512GB 级单器件为推理集群提供了介于 HBM（数十 GB/栈）与 SSD 之间的新容量档，内存墙的产业化解法进入标准化阶段。

（来源：[SK hynix Newsroom](https://news.skhynix.com/en/hbf-at-fms-2026/) · [StorageNewsletter](https://www.storagenewsletter.com/2026/08/05/fms-2026-sandisk-and-sk-hynix-advance-global-standardization-of-high-bandwidth-flash-with-release-of-first-ocp-technical-specification/)）

### Claude 企业版新增 inference hooks，prompt 先过企业 DLP 再进模型

Claude 企业版 8/5 起可让每条 prompt 先过企业自建 DLP 审查再进模型。功能名 **inference hooks**（beta）：企业在自有基础设施上部署审查服务器，Claude 的每条 prompt 与工具调用先经其 allow/deny 判定，覆盖对话、**Claude Code** 与 Cowork；webhook 协议可对接 Netskope、Palo Alto Networks、Zscaler 等现有 DLP 栈。限制也明确：仅二元放行/拦截、仅检查 prompt 侧、不检查图像内容。落地路径：支持 **shadow mode** 灰度——安全团队可先只记录不拦截、量出误拦率，再切强制模式；受监管行业（金融、医疗）部署 Claude 的合规断点由此打通。

（来源：[Anthropic 官方博客](https://claude.com/blog/claude-enterprise-inference-hooks) · [TNW](https://thenextweb.com/news/anthropic-inference-hooks-dlp-claude-enterprise)）
